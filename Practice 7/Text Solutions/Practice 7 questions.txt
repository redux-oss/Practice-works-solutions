Що насправді відбувається під час x = x + 1?
x = x + 1: це не рівняння, а команда: обчислити праву частину (взяти поточне x, додати 1), потім записати результат у x. Тому «x дорівнює x плюс 1» тут не парадокс.
Чим = відрізняється від ==?
= і ==: = присвоює значення (x = 5), == порівнює й дає true/false (x == 5). У Java if (x = 5) не скомпілюється, у C скомпілюється й буде помилкою.
Коли брати while, а коли for?
while чи for: for, коли кількість повторень відома заздалегідь (перебір 0..n−1, елементів масиву). while, коли невідомо, скільки разів (читати, доки не порожньо; шукати, доки не знайдемо).
Чи можна написати будь-яку програму, маючи лише if і while?
Лише if і while: так, цього достатньо для будь-якої обчислюваної програми (разом зі змінними й арифметикою). for, switch та інше лише зручність.
break посеред циклу — зручність чи поганий стиль?
break: зазвичай зручність, якщо вихід з циклу очевидний (знайшли елемент, далі шукати нема сенсу). Поганий стиль, коли розкиданий по кількох місцях і плутає логіку; тоді краще переписати умову циклу.
Як переконатися, що цикл колись завершиться?
Завершення циклу: переконайтеся, що 1) тіло циклу наближає умову виходу (лічильник змінюється в потрібний бік, число зменшується); 2) є величина, яка кожну ітерацію строго змінюється й обмежена (наприклад, n зменшується до 0); 3) умова не залежить від чогось, що ніколи не зміниться. Типова помилка: забули i++ або записали i <= n замість правильного напрямку.
